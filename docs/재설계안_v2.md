## 3. 수집 설계 — 2-트랙

### Track A. 시장 전체 (가전 카테고리 전반)
- **카테고리 매핑 테이블** 신설: 우리 66개 카테고리 ↔ 다나와 `cate` 코드 (예: 스팀다리미=10325673). 1회 수작업+검증 후 고정.
- 카테고리당 **인기순 상위 2~4페이지(약 60~120개 모델)** 수집 — 시장 평균/중앙값/추세·급변 탐지에 충분, 부하 최소.
- 추출 필드: pcode(식별자) · 상품명 · 대표 최저가 · 스펙 문자열(용량 추출 입력) · 카테고리 계층 · 몰 수(shopCount) · 등록일.
- 효과: 다나와 카탈로그는 **모델 단위 정규화가 이미 되어 있어** 네이버 대비 중복·잡음(리셀러·별매품) 대폭 감소. 기존 분류·용량 시스템은 2차 검증용으로 유지.

### Track B. 자사 운영 카테고리 정밀 (쿠쿠 라인업)
- `productlist.xlsx`의 **쿠쿠 모델코드 전수**를 다나와 검색으로 트래킹.
- 모델별: 최저가 + 몰별 오퍼(몰코드→몰명 매핑) → **"우리 모델이 지금 어디서 얼마에 팔리는가"**.
- 같은 cate의 Track A 데이터와 결합 → 동급(용량 밴드) 경쟁 포지셔닝(기존 로직 재사용).
- "자사 운영 카테고리" 정의 = 카탈로그에 모델이 있는 카테고리 (현 `has_own_lineup` 로직 유지).

### 수집 매너·안정장치 (이번 사고의 교훈 반영)
- 요청 간격 1.5~2초, 고정 UA, 재시도 2회 — 일 2회 cron 기준 전체 수집 ≈ 10~15분.
- **파서 자가진단**: 수집 결과 0건이면 "성공"이 아니라 **실패로 처리**하고 기존 데이터를 덮지 않음 (이번에 빈 수집이 success로 배포된 문제 방지).
- **구조변경 감지**: 파싱 성공률이 임계 미만이면 workflow 실패 → GitHub 알림.

## 4. 데이터 영속성 — 이력 소실 재발 방지 (중요)

| 문제 | 대책 |
|---|---|
| Actions 캐시는 7일 미사용 시 삭제 | **가격 이력을 저장소에 커밋** — `data` 브랜치에 SQLite DB(또는 월별 스냅샷 jsonl) 푸시. 캐시는 성능 보조로만 사용 |

| 빈 수집이 사이트를 덮음 | **export 가드**: 본품 N건 미만이면 배포 중단 + 직전 데이터 유지 |

## 5. 데이터 모델 변경 (최소 수정)

- `Product`: `danawa_pcode`(신규 식별자, unique) 추가 — `model_key`는 병행 유지(자사 매칭용)
- `PriceSnapshot`: `source='danawa'`, `mall`=다나와 몰코드→몰명
- `DanawaSpec` 테이블 → 본 수집으로 흡수(스펙이 목록 JSON에 포함되므로 별도 보강 수집 불필요)
- Category/Brand/용량밴드/is_accessory·is_rental 로직: 그대로 재사용
- 과거 네이버 수집 데이터: 보존하되 `source='naver'`로 구분 (이력 그래프에서 구간 표시)

## 6. 대시보드 구성 (프론트 90% 재사용)

export JSON 계약(products/ranking/positioning/kpi…)을 동일하게 유지하므로 **3탭 UI는 거의 그대로**:

| 탭 | 유지 | 보강 |
|---|---|---|
| ① 시장 현황 | KPI·상세필터·주간요약·변동랭킹+비교·카테고리표·드릴다운 전부 | 제품 링크→다나와 상품페이지(pcode), 몰 수(shopCount) 표시 |
| ② 쿠쿠 분석 | 포지셔닝 양방향 막대표 | **모델별 최저가 몰 칼럼**("지금 최저가는 어느 몰"), 운영 카테고리 필터 기본값 |
| ③ 알림·이벤트 | 변동 알림·이벤트 캘린더 | 수집 상태 배지(다나와/데이터랩/환율 최근 성공 시각) |

## 8. 리스크와 한계

- **다나와 구조 재변경**: 파서 가드로 조기 감지, 수집 실패 시 기존 데이터 보존 — 사이트가 비는 일은 없음.
- **차단 가능성**: 저부하(일 2회, 카테고리당 수 페이지)로 위험 낮음. 차단 시 간격 확대·수집량 축소로 대응.
- **데이터 성격 변화**: 네이버(리스팅 단위, 잡음 많음) → 다나와(모델 단위, 정규화됨). 비교 정확도는 오히려 ↑, 단 과거 네이버 데이터와의 가격 수준 연속성은 끊김(소스 구분 표기).
- **이용 범위**: 사내 분석용 저부하 수집 — 데이터 외부 재판매·대량 재배포는 하지 않음.
